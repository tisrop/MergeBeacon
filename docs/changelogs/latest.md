# 更新日志

这里记录每个版本最值得关注的体验变化，不逐条翻译提交记录，也不要求与 Release Notes
一一对应。如果你只想知道“升级后哪里更好用了”，看这里就够了。

## v0.14.0（2026-08-07）

这一版让 PR/MR 更容易按人来找，负责和测试的状态也更清楚，列表用起来也更稳。

### 按评审人筛选，更快找到 PR

- GitHub、GitLab 和 Gitee 的 PR/MR 列表都支持按评审人筛选，只看某个负责人过目的
  变更更省事。
- 筛选可以和搜索等条件一起用，锁定归属某位评审人的改动更快。

### 负责人与测试者状态更清楚

- PR/MR 详情页会展示负责人和测试者的相关状态，并支持点击跳转到外部页面，跟进更方便。
- Gitee 的文案更统一：作者改叫创建者、审查者改叫审查、测试者改叫测试，概念不再混淆。

### 列表浏览更稳、启动更快

- PR 列表重新使用首屏同步加载，进入应用翻列表更快。
- 修复了晚到的旧请求可能覆盖当前结果、单页时显示分页条等问题，浏览时不会突然跳变。

## v0.13.0（2026-08-01）

这一版把评审时间线整理得更清楚，也照顾到偏好减弱动效的用户。

### 评审时间线更清楚

- PR / MR 中的「整体评审」和「一般评论」会分开归类，GitLab 和 Gitee 也能正确识别，
  不再把评论和评审混在一起。
- 进度概览把整体评审、一般评论、评论线程和行内评论分开统计，评审进展一眼就能看清。
- 评审记录按时间顺序编号展示，对话较长时也更容易顺着往下看。

### 动效更照顾个人偏好

- 系统开启「减弱动态效果」后，跳转到设置项和评审线程会直接瞬时滚动，不再平滑滚动，
  减少不必要的晃动。

## v0.12.0（2026-08-01）

这一版界面支持中英文了，AI 评审也能随时停，找 PR 和翻仓库都更快。

### 界面可以中英文切换

- 界面语言可以在简体中文和英文之间切换，切换后立即生效，重启后也会记住你的选择。
- AI 评审的意见语言可以跟随界面，也可以单独指定，设置只影响之后开始的评审。
- 原生菜单等桌面入口的文案会随界面语言一起更新，不会中英文混着出现。

### AI 评审能随时停，也更稳定

- AI 评审进行中可以随时中断，不用等它跑完，也不会被当成错误提示。
- 评审结果解析更稳定，模型输出带多余文字时也能正确提取结论。
- 默认模型更新为更合适的版本，不同平台都能得到更可靠的评审。

### PR/MR 搜索筛选更强

- GitHub 的 PR 列表支持按标题、作者等条件搜索和筛选，找目标更快。
- GitLab 和 Gitee 也支持同样的搜索与筛选，三个平台体验一致。
- 列表分页、筛选和状态加载更稳定，切换条件时不会串到旧数据。

### 常用仓库星标置顶

- 常用仓库可以星标置顶，一打开就能找到。
- GitHub 仓库列表加载更快，切换仓库更顺畅。

### 详情页和设置更顺手

- PR/MR 描述或评论里的视频附件可以直接播放，加载失败会保留原始链接。
- 设置页拆分了普通设置与更新入口，想找的东西更快定位。
- 关闭设置会回到打开前的页面，而不是一直停在设置里。
- 详情页评审布局重新整理，侧栏重复的创建入口也清理掉了。

## v0.11.0（2026-07-29）

这一版让 Diff 也能翻历史了，Issue 编辑更方便，界面细节也打磨了一圈。

### Diff 也能按提交翻历史

- 查看 PR / MR 的 Diff 时，可以切换到单个提交的改动视图，只看那一次提交做了什么。
- 按住 Shift 再选另一个提交，可以只看这两个提交之间的差异。区间内只读查看，不会误操作。
- Diff 文件列表里新增复制路径按钮，快速复制文件路径供分享或命令行使用。

### Issue 和 PR / MR 信息更完整

- Issue 详情页可以直接编辑标题和描述，不用像以前一样只能看不能改。
- 标签在 Issue 和 PR / MR 详情页都能显示背景色，扫一眼就能区分不同分类。
- 审核人员的检视状态（已批准、待审核、需修改）直接在详情页展示，谁还没批一目了然。
- 编辑 PR / MR 元数据时可以预览描述，填完确认前先看效果。

### 操作确认一步，列表不乱跑

- 关闭 PR 或 Issue 时增加确认步骤，防止手滑误关。
- 创建 Issue 后列表自动刷新，新条目立即可见。
- 切换仓库时筛选条件自动重置并优先加载新仓库，不会看到旧仓库的内容。
- 创建 PR / MR 时支持手动刷新分支列表，新推的分支不用退出重进。

### 小细节也更顺手

- 详情页的代码块可以正常复制了，正文链接和折叠区域渲染也更准确。
- 标题中的外部链接恢复跳转。共享控件的样式和标签文案统一后，整体更协调。
- 各平台新增分类设备下载指南，按操作系统就能找到对应安装包。

## v0.10.0（2026-07-26）

这一版让创建 Issue 和 PR / MR 更省事，更新提示也更不容易错过。

### 创建 Issue 也能跟仓库约定对齐

- 创建 Issue 时可以读取仓库已配置的模板，一键带出标题、正文和推荐标签。
- 标签只能从仓库已有标签里选择，避免手写错误名称导致创建失败。
- 模板和标签加载失败时可以重试，切换仓库后会重新拉取，不会串用旧仓库的选项。

### PR / MR 草稿有模板，也能让 AI 先写一版

- 创建 PR / MR 时可以应用仓库模板，并选择只填空白字段或覆盖已有内容。
- 可以让 AI 根据当前提交和 Diff 生成标题与描述草稿；生成中可取消，不会当成错误打断。
- Diff 过大时会明确说明截断边界，避免误以为模型读完了全部改动。

### GitLab 描述里可以直接粘贴图片

- 在 GitLab 创建 MR 时，描述编辑框支持粘贴 PNG、JPEG、GIF 或 WebP，单张不超过 5 MiB。
- 上传成功后会插入可预览的 Markdown；当前平台不支持或能力未加载完成时，会给出清楚提示。

### 有新版本时会主动提醒

- 后台检测到可用更新时会弹出提示，不必只靠设置页才能发现。
- 设置页的更新说明展示更清晰，方便先读再决定是否安装。

## v0.9.0（2026-07-25）

这一版主要打磨日常评审体验：界面更清爽，找代码和翻列表也更快。

### 更舒服的界面

- 重新整理了主要页面的颜色、间距、层级和交互状态。信息很多时更容易分清重点，长时间评审也
  不那么累。
- 统一了表单、卡片、侧栏和弹出内容的视觉细节，页面之间切换时更连贯。
- 调整了 AI 评审筛选等容易拥挤的控件，小窗口下也能更完整地看到选项。

### 在 Diff 里直接找代码

- 查看文本 Diff 时，可以使用 `⌘/Ctrl + F` 搜索当前文件。
- 支持区分大小写、全词匹配和正则表达式，并能快速跳到上一个或下一个结果。
- 搜索只影响当前文件，不会打断正在进行的评论和评审。

### 翻页不再只能一步一步来

- PR / MR 列表现在可以直接跳到指定页。
- 可以按需要选择每页显示 10、20、50 或 100 条记录。
- 修复了结果数量重复显示等小问题，列表信息更干净。

### 更稳定的图片预览

- 修复了图片第一次打开时偶尔不显示或显示旧内容的问题。
- 快速切换文件时，较早返回的图片不会再覆盖当前正在查看的文件。

## v0.8.0（2026-07-24）

这一版让大型 PR / MR、图片变更和问题排查都更从容。

### 图片变更可以直接看

- 支持在 Diff 中预览常见图片的变更前后内容，不必下载后再手动比较。
- 图片过大、格式无效或平台无法提供内容时，会明确说明原因，不会留下空白区域让人猜测。
- 修复了 Fork 和跨仓库 PR / MR 获取图片源文件不准确的问题。

### 大型改动也有清楚的边界

- 创建 PR / MR 前会尽可能完整地加载 Commit 和 Diff，并在平台只返回部分结果时明确提示。
- 即使预览不完整，也不会错误阻止一个本来可以正常创建的 PR / MR。
- Closed 和 Merged 列表支持继续分页浏览，不再只看到第一页。

### 找仓库、选参与者更省事

- 侧栏新增仓库搜索，仓库较多时不用反复滚动查找。
- Reviewers、Assignees、标签等候选项支持搜索；加载失败后可以直接重试。
- 设置入口和侧栏状态进一步统一，加载过程中不再显示容易误点的“加载更多”。

### 更新与问题排查更可靠

- 自动更新支持跟随系统代理，企业网络和代理环境下更容易正常检查及下载更新。
- 错误提示带有可用于定位问题的请求编号，并会在本地保留经过脱敏的错误日志。
- 日志不会记录 Token、API Key、仓库代码或完整的私有服务地址。

## v0.7.0（2026-07-20）

这一版补上了跨平台创建 PR / MR 的完整入口，也让 AI 评审结果更容易继续使用。

### 在应用里创建 PR / MR

- GitHub、GitLab 和 Gitee 都可以直接创建 PR / MR。
- 可以选择目标仓库、Fork 源仓库、源分支和目标分支，并按平台能力添加参与者与标签。
- 创建前可以编辑和预览 Markdown 描述，查看 Commit 列表、完整 Diff，或只看某个 Commit 的改动。
- 如果参与者或标签只有部分写入成功，应用会保留已经创建的 PR / MR，并告诉你哪些内容需要补充。

### AI 评审可以接着上次继续

- 评审结果按仓库、PR / MR 和提交版本保存在本地，重新打开后仍能找到。
- 历史记录会说明使用的模型、评审范围、关注方向和提交版本，方便判断结果是否仍然适用。
- AI 建议和人工评论使用统一草稿；真正提交前仍由你检查和确认。
- PR / MR 出现新提交后，旧结果和旧草稿会被标记为过期，避免把评论发到已经变化的代码上。

### 键盘操作更顺手

- 下拉选项支持使用方向键循环浏览。
- 搜索、输入法输入、焦点和选中状态更加一致。
